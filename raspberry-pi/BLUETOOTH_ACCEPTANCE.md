# 手机蓝牙控制盲文板：验收步骤

按顺序执行并记录结果。任何一项不通过，先停在该项排查；不要跳过无电磁铁电源测试。参照 `../hardware/pcb/README.md` 和当前 PCB 接线图核对硬件。

## A. 无硬件离线检查

- [ ] 在电脑或 Pi 的 `raspberry-pi` 目录运行 `python3 -m unittest discover -s tests -v`，所有测试为 `OK`。
- [ ] 运行 `python3 Braille.py --simulate --text hello`，输出五行；首行 `h` 的六位点阵为 `110010`。
- [ ] 确认手机使用本次源码构建的 App，Pi 使用本次完整 `raspberry-pi`，两端版本一致。

## B. 只给 Pi 供电，线圈 7.4V 保持关闭

- [ ] 断电核对当前 PCB 的六路 GPIO、板载驱动、续流二极管、公共地和独立电源；随后仅打开 Pi 的 5V 电源。
- [ ] 停止所有旧 GPIO 程序，执行 `python3 Braille.py --bluetooth --mute --text hello`。终端显示 `Bluetooth SPP profile ready`，没有 GPIO 占用报错。
- [ ] 手机系统蓝牙与 Pi 配对；App 的 Word library 选择 `hello`，点 **Send to Braille board → Step 1**，状态显示已连接。
- [ ] 点 **Send word to board**，App 回执为 `h · letter 1 of 5 · dots 110010`；Pi 终端显示蓝牙 load 事件。
- [ ] 按盲文板实体 **Next**，Pi 终端显示 `e`；再按实体 **Previous**，回到 `h`。手机端没有重复的翻页按钮。
- [ ] 发送后返回词库或上一页，App 不闪退，Pi 蓝牙保持连接；重新进入发送页可直接发送另一个词。点 **Disconnect board** 后 Pi 仍运行，可再次连接。
- [ ] 等待当前最多 90 秒通电窗口结束，GPIO 驱动输出应为低电平；若命令覆盖了 `MAX_ON_SECONDS`，按实际覆盖值计时。
- [ ] 在冷却期间连续按实体 Next，实际输出不得延长连续通电窗口。
- [ ] 断开手机蓝牙再重连，新的指令仍能收到回执；旧连接遗留消息不应触发输出。

如果没有示波器或逻辑分析仪，B 段可以先只核对终端和 App 回执；不要把普通万用表读不到短脉冲误判为无输出。接线位置见 `../hardware/pcb/README.md` 及 PCB 原理图。

## C. 逐路线圈与盲文点

- [ ] 先关 Pi 和 7.4V，确认第一路线圈的额定电压、MOSFET G/D/S、续流二极管方向与公共地，再按原硬件文档只接第一路。
- [ ] 确认线圈额定参数允许目标通电时间后，先开 Pi，再开现有稳压 7.4V 电源。从 App 发送以 `a` 开头的词，点 1 升起，最多 90 秒后释放（或按启动命令覆盖值释放）。
- [ ] 依次从 App 发送以 `b`、`c`、`d`、`e`、`f` 开头的词，确认点位。触读正面点序为左列 1/2/3、右列 4/5/6；逐路确认无颠倒。
- [ ] 发送 `hello`，按板上的实体 Next 逐字观察；冷却期的请求应等待，不能让线圈持续吸合。
- [ ] 观察线圈、电源、MOSFET 的温升与异常声响。任一路持续吸合、明显发热或电源异常，立即切断 7.4V 并排查。
- [ ] 等待全部点按限时自动释放。结束时先关 7.4V，再 Ctrl+C 停主程序。

## D. 配网与异常处理（可选）

- [ ] 线圈电源关闭，在 App 的 Pair your board 蓝牙页执行 Wi-Fi 配网，收到 `SUCCESS` 与 IP，或明确的 `FAIL`；主程序不能因配网而停掉 GPIO 限时循环。
- [ ] 在蓝牙断开、未配对或 Pi 程序未启动时，App 显示未连接，不能误报已展示盲文。
- [ ] 非法字符、超长文本及未知命令被 Pi 拒绝；不会直接控制 GPIO 或改变线圈通电时长。

当前仓库的自动测试只能覆盖协议与模拟 GPIO；Pi 蓝牙、真实 Android 连接、线圈动作和热表现必须按 B–D 在实机记录。验收记录建议填写手机型号与 Android 版本、Pi OS 版本、线圈电源实测电压、每项通过/失败、异常日志与点位照片。
